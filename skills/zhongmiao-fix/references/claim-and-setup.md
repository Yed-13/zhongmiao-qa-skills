# 领题与开工准备

## 读任务表

- 保留原表，在副本上做标记；不改原表的内容和样式。
- 用 `scripts/read_issue_sheet.py` 连底色一起读。它报的是**直接填充色**；表里有条件格式时会提示，那时要在表格软件里看实际显示。
- 表头一般会写颜色的含义（例如「蓝底行 = 影响推荐知识点」，这类行常由别人负责或另有安排）。按表头说明和用户的排除规则判断，不要只凭颜色猜。
- 一行里要读全：问题、现象说明、涉及知识点、严重度、当前状态、主记录 / PR、代码线索。「代码线索」里的行号是当时的，要在最新 main 上重新定位。
- 「下一个」按表格顺序 + 排除规则找。用户点名的编号以用户为准。

## 查重（每次都做，表格状态经常落后）

1. `scripts/check_issue_status.sh <主仓库> <编号...>`：查 upstream/main 的提交标题和正文、分支名，并用 git 拉最近 300 个 PR 的提交（`refs/pull/<号>/head`，同学从 fork 开的 PR 也在里面），列出提到这个编号的 PR 和它是否已合并。全程只用 git，不打开 GitHub 网页。
2. git 看不到 PR 标题和开关状态：命中「未合并」的 PR、或者编号没写进提交说明的情况，请用户在 GitHub 的 PR 列表里确认（按编号、组件名搜），把结果告诉你。
3. 找到已合并的提交，读完整提交说明：`git log -1 --format=%B <sha>`。作者常写明「另两处未动」「范围外」「待教授决定」——这就是剩下的部分。
4. 结论三选一，报告给用户再继续：
   - 已完全修好 → 给出 PR 链接，停下，让用户换题。
   - 部分修好 → 列出剩下的部分和它们的状态（例如「待教授决定」的不要擅自做）。
   - 没人做 → 开工。

## 编号 → 代码

- 表里的知识点编号（K0xx）是任务表自己的编号体系，**不一定**和仓库里其他文档（例如知识关系草稿）的 K 编号一致。按这一行写的场景/组件名去仓库找，再用实际单元内容确认。
- 代码使用的知识点 ID 形如 `g<年级>-math-<主题>`。在 `server/scripts/` 下的单元快照目录（例如 `ans/`、`beta_*_units/`、`m024_regen_units/`）和前端世界组件里搜它。
- 仓库快照不等于生产库现状；本地旧快照里有问题，不能证明正式站今天还有。正式站没核对的写「未测」。

## 写成可验收的一句话

把「题目跑题」「画面不对」改写成能检查的句子：在哪个课/档/题，做什么操作，应该看到什么。顺便写下：已知事实（看到的、量到的）和待验证判断（推测的原因）。

## 建工作目录

```bash
bash scripts/new_task_worktree.sh <主仓库目录> <任务名>   # → ../<任务名>-pr，分支 qa/<任务名>-pr
```

- 远端约定：`origin` = 你自己的 fork，`upstream` = 教授仓库。没有 upstream 就先 `git remote add upstream <教授仓库地址>`。
- 第一次克隆才需要 clone；已有仓库不要重新克隆覆盖。
- 主目录有未提交改动时先看清来源，不要 `reset --hard`、不要在脏目录里 rebase。需要保留时存补丁（`git diff`、`git diff --cached`），未跟踪文件单独备份；`.env.local` 之类本机配置不进 PR、不进公开附件。
- 两个独立问题各一个分支一个 PR。共享文件里的改动按逻辑拆，不要把整个文件复制过去，也不要从混合分支开两个内容相同的 PR。

## 每次开始前的基线检查

```bash
git status --short
git branch --show-current
git rev-parse HEAD
git fetch upstream main
git rev-list --count HEAD..upstream/main   # 上游独有的提交数（分叉时不等于“落后多少”）
git diff --stat; git diff --cached --stat
```

## 读仓库规则

`AGENTS.md`、`CLAUDE.md`、`docs/IRON_LAWS.md`，涉及 /tutor 再读 `docs/K12_LEARNING_DECISION_BASELINE.md`。与修复最相关的几条铁律（以仓库原文为准）：

- 第 17 条：讲解示范与第 1 题必须是同一个知识点；「不与题目重复」只指情境和数字。
- 第 19 条：情境是题目的对象，不是包装纸；长文字在替一张图干活时应配图。
- 第 20 条：3D 互动装置不许被提示/题卡/气泡遮挡，判据是量出来的重叠。
- 第 21/23/24 条：判据要回答真问题，失效时往红里错；门禁验的是形式不是内容；量具要先喂必中/必不中的输入证明它不是静默失效。
- 项目硬规则：i18n 用 `t()`，zh-CN 与 en 同步；用 `var(--axis-*)` 设计变量；PR 前跑 Guardian。
